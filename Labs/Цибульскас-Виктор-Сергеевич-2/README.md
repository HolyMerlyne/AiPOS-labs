## Вариант 11(3)
### Требования к реализации UDP-сервера 
> **«Подсчет контрольной суммы ASCII символов для каждой из последовательностей из 10 символов потока клиента и отсылка контрольной суммы после приема каждой из цепочек клиенту».**
*Функциональные особенности сервера:*
- Сервер ожидает входящие датаграммы на порту `666` (с возможностью передачи другого порта в аргументах: `java UdpServer 6666`).
- Поток символов от клиента может поступать порциями любой длины. Сервер ведет строковый буфер входящего потока для каждого клиента (по сетевому адресу `SocketAddress`).
- По мере поступления символов, пока в буфере $\ge 10$ символов, извлекается блок из 10 символов, вычисляется арифметическая сумма числовых кодов ASCII входящих в него символов ($\sum_{i=0}^9 \text{ASCII}(c_i)$), и результат незамедлительно отправляется клиенту.
- Остаток менее 10 символов сохраняется в буфере сессии клиента в ожидании последующих датаграмм.
- Обработка команды разрыва соединения: `disconnect <адрес> <порт>`.
### Требования к реализации UDP-клиента
1. **Ввод символов с отсылкой введенной строки по нажатию на клавишу:** `End`
   - При запуске клиента (`java UdpClient` или `./run_client.sh`) **сразу открывается графический интерфейс (GUI Swing)**.
   - В графическом интерфейсе реализован глобальный перехват нажатия клавиши `End` (`KeyEvent.VK_END` на стандартной клавиатуре и `Fn + стрелка вправо` на MacBook) через `KeyboardFocusManager`. Отправка также возможна по нажатию Enter в поле ввода и по кнопке «Отправить (End)».
2. **Ведение файла протокола событий (`client_protocol.log`), включающих:**
   - `2)` передаваемую серверу строку и время передачи строки;
   - `3)` принимаемую от сервера строку и время приема строки.
   - Протоколирование реализовано средствами `java.util.logging` в гарантированной кодировке **UTF-8** с отметками времени до миллисекунд.
3. **Возможность разрыва соединения при помощи команды:** `disconnect <адрес> <порт>` (признак `+`).
4. **Задание в программе клиента специальной команды и параметров подключения к серверу:** `connect <адрес> <порт>` (вариант `1)`).

### Ограничение набора символов

Поток данных должен состоять только из **ASCII-символов** (коды `0..127`):

- клиент не отправляет строку, если в ней есть не-ASCII символы, и показывает сообщение об ошибке;
- сервер отклоняет не-ASCII датаграммы ответом `ERROR: ...`, не добавляет их в буфер и не учитывает в контрольной сумме.

## Запуск

Все команды выполняются из каталога лабораторной работы. Из корня репозитория `AiPOS-labs` перейдите в него:

```bash
cd Labs/Цибульскас-Виктор-Сергеевич-2
```

- Компиляция исходников:

```bash
javac -encoding UTF-8 ChecksumUtil.java UdpServer.java UdpClient.java
```

- Запуск сервера (по умолчанию используется порт `666`):

```bash
java -Dfile.encoding=UTF-8 UdpServer
```

  На macOS/Linux порт `666` требует прав root:

```bash
sudo java -Dfile.encoding=UTF-8 UdpServer
```

  Для проверки без прав root можно указать другой порт, например `6666`:

```bash
java -Dfile.encoding=UTF-8 UdpServer 6666
```

- Запуск клиента:

```bash
java -Dfile.encoding=UTF-8 UdpClient
```

  В окне клиента выполните подключение:

```text
connect 127.0.0.1 666
```

  Если сервер запущен на другом порту, укажите его, например:

```text
connect 127.0.0.1 6666
```

- Консольный режим клиента (без GUI):

```bash
java -Dfile.encoding=UTF-8 UdpClient --console
```
