## Задание по варианту 6
- **Сервер (задание №7)**: в потоке символов принимает команду
  `find <строка> <имя файла>`, ищет строки, содержащие `<строка>`,
  отсылает клиенту **количество найденных строк**. Если ни одной
  строки не найдено — отсылает сообщение об окончании сеанса и
  разрывает соединение.
- **Клиент (задание №2)**:
  1) специальная команда `connect <адрес> <порт>`;
  2) автоматическое подключение к серверу по умолчанию
     (`127.0.0.1:666`) при запуске.
  Дополнительно (из сноски к Таблице 3) ведётся журнал событий
  (`logs/client.log`, `logs/server.log`, `logs/udp-*.log`):
  время начала/окончания соединения, отправленные и принятые строки
  с отметкой времени.

## Требования
- JDK 8+ (`javac -version`, `java -version`).
- VS Code c расширением **Extension Pack for Java** (Microsoft).

## Сборка
Из корня проекта:
```bash
javac -encoding UTF-8 -d bin src/*.java
```
В VS Code: `Ctrl+Shift+B` (задача `compile-all`) — если добавлен
`.vscode/tasks.json`; либо через меню **Terminal → Run Build Task**.

## Запуск (терминал VS Code, 4 терминала)

Терминал 1 — TCP-сервер:
```bash
java -cp bin TcpServer
```
Терминал 2 — TCP-клиент:
```bash
java -cp bin TcpClient
```
Терминал 3 — UDP-сервер:
```bash
java -cp bin UdpServer
```
Терминал 4 — UDP-клиент:
```bash
java -cp bin UdpClient
```

Чтобы запустить **несколько TCP-клиентов одновременно**, откройте
ещё один терминал и повторите `java -cp bin TcpClient`.

## Сценарии проверки (для отчёта)

| Ввод в клиенте                 | Ожидаемый ответ сервера |
|--------------------------------|-------------------------|
| `find Hello test1.txt`         | `RESULT: найдено строк = 3` |
| `find apple test2.txt`         | `RESULT: найдено строк = 2` |
| `find zzz test1.txt`           | `RESULT: строка 'zzz' не найдена. Сеанс завершён.` + разрыв |
| `find foo missing.txt`         | `ERROR: файл 'missing.txt' не найден. Сеанс завершён.` + разрыв |
| `hello`                        | `ERROR: ожидается команда формата: find <строка> <имя файла>` |
| `connect 127.0.0.1 666`        | переподключение к серверу |
| `quit`                         | выход |

Проверка через **telnet** (Windows: Панель управления → Программы →
Включение компонентов Windows → Клиент Telnet):
```cmd
telnet 127.0.0.1 666
find Hello test1.txt
quit
```

## Журналы
После сеанса откройте:
```
logs/client.log
logs/server.log
logs/udp-client.log
logs/udp-server.log
```
Пример строки журнала клиента:
```
INFO: CONNECTED to 127.0.0.1:666 at 2025-11-10 14:33:05.123
INFO: SENT => find Hello test1.txt
INFO: RECV <= RESULT: найдено строк = 3
INFO: DISCONNECT at 2025-11-10 14:33:10.456
```
Это закрывает пункты «время начала/окончания соединения»,
«отправляемая строка + время», «принимаемая строка + время».

## Пояснения к реализации (для защиты)
- **TCP** — потоковый (`Socket`/`ServerSocket`), гарантирует
  доставку и порядок; используем `BufferedReader`/`PrintWriter`
  с `autoFlush=true` (без этого данные «висят» в буфере).
- **Многоклиентность** — отдельный `Thread` на каждый принятый
  `Socket` (`ClientHandler` в `TcpServer`).
- **UDP** — без установки соединения (`DatagramSocket`/
  `DatagramPacket`), нет гарантии доставки; в клиенте
  `setSoTimeout(3000)` для защиты от «зависания».
- **Журналирование** — `java.util.logging` (рекомендовано в сноске
  к Таблице 3 методички).
