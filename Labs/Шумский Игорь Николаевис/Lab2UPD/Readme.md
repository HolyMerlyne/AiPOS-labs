## Описание реализации

В ходе работы было разработано клиент-серверное приложение на языке Java с использованием библиотеки `java.net`. Приложение реализует обмен данными по протоколу **UDP** (User Datagram Protocol) — протоколу без установления соединения, в котором данные передаются независимыми датаграммами.

### Сервер

- Ожидает датаграммы на порту 666 (`DatagramSocket`)
- В отличие от TCP-сервера, **не использует** методы `accept()` и `listen()`, так как UDP работает без установки соединения
- Для каждого клиента, присылающего данные, сервер **самостоятельно хранит состояние** — буфер накопленных символов, используя `ConcurrentHashMap<SocketAddress, StringBuilder>`, где ключом является адрес клиента (`SocketAddress`)
- При накоплении 64 символов формирует отчёт о частоте каждого символа в формате «символ-количество» и отправляет его клиенту в виде отдельной датаграммы
- Если в группе из 64 символов встречается менее 3 уникальных символов, сервер отправляет сообщение об ошибке и **логически разрывает соединение**: адрес клиента добавляется в «чёрный список» (`ConcurrentHashMap.newKeySet()`), после чего все последующие пакеты от этого клиента игнорируются
- Поддерживает команду `disconnect` для корректного завершения сеанса — при её получении буфер клиента удаляется, а адрес добавляется в чёрный список
- Многопоточность не требуется: обработка каждого пакета происходит в основном цикле сервера, так как UDP не создаёт выделенных потоков для клиентов

### Клиент

Клиент представляет собой **GUI-приложение** на базе Swing с окном, содержащим:
- строку состояния (текущее состояние соединения),
- область вывода ответов сервера и логов (прокручиваемое текстовое поле),
- поле ввода строки,
- кнопку Disconnect.

**Особенности реализации:**
- Автоматическое подключение к серверу `localhost:666` при запуске (инициализация `DatagramSocket` без привязки к конкретному порту — ОС сама назначает свободный порт)
- Отправка строк происходит по нажатию клавиши **Home** (реализовано через механизм Key Bindings в Swing: `InputMap` и `ActionMap` перехватывают `VK_HOME` в поле ввода)
- Приём ответов от сервера выполняется в **отдельном потоке** (`Thread` с флагом `daemon`), который блокируется на методе `socket.receive()`. Обновление GUI происходит через `SwingUtilities.invokeLater()` для соблюдения потокобезопасности Swing
- Ведение файла протокола событий `client_log.txt` (в каталоге запуска клиента). В файл записываются с метками времени:
  - момент установки соединения и его параметры (хост и порт),
  - отправленные серверу строки и время их передачи,
  - принятые от сервера строки и время их приёма,
  - момент и причина закрытия соединения (пользователем или сервером),
  - сообщения об ошибках подключения
- При получении от сервера сообщения о разрыве соединения (менее 3 уникальных символов) клиент:
  - устанавливает флаг `isDisconnected = true`,
  - блокирует поле ввода (`inputArea.setEditable(false)`),
  - физически закрывает сокет (`socket.close()`),
  - выводит предупреждающее диалоговое окно
- Корректное закрытие окна через кнопку Disconnect или крестик в любой момент работы (в том числе после разрыва соединения сервером)

## Запуск

### Требования

- ОС Windows (или любая ОС с установленной JDK)
- JDK (Java Development Kit) версии 8 или выше
- Свободный порт 666

### Порядок запуска

1. Разместите файлы `UDPServer.java` и `UDPClientGUI.java` в рабочем каталоге

2. Скомпилируйте классы:
   ```bash
   javac UDPServer.java UDPClientGUI.java
   ```

3. Запустите сервер:
   - В отдельном окне терминала запустите `java UDPServer`
   - В консоли появится: `UDP Server started on port 666`

4. Запустите клиент (не закрывая окно сервера):
   - Запустите в консоли `java UDPClientGUI`
   - Откроется графическое окно с автоматическим подключением к серверу

5. Проверка работы:
   - Введите текст в поле ввода и нажмите клавишу **Home** — текст отправится на сервер
   - Введите ровно 64 символа (например, `aaaabbbbccccddddeeeeffffgggghhhhiiiijjjjkkkkllll12345678901234`) и нажмите Home — сервер вернёт отчёт о частоте символов
   - Введите 64 одинаковых символа (например, 64 буквы 'a') и нажмите Home — сервер вернёт ошибку и разорвёт соединение; поле ввода клиента заблокируется
   - Введите команду `disconnect` и нажмите Home для корректного завершения сеанса

## Вывод

В ходе выполнения лабораторной работы было успешно разработано клиент-серверное приложение на языке Java с использованием библиотеки `java.net` по протоколу **UDP**. Освоены основные отличия UDP от TCP: отсутствие установления соединения (`connect`/`accept`), использование классов `DatagramSocket` и `DatagramPacket` вместо потоковых `Socket` и `ServerSocket`, независимая передача каждой датаграммы.

Реализованы механизмы хранения состояния клиентов на сервере с помощью `ConcurrentHashMap` (буферы накопления символов и «чёрный список» отключённых клиентов), что необходимо в UDP, так как протокол не поддерживает постоянные соединения. Логический разрыв соединения эмулируется через добавление адреса клиента в чёрный список и последующее игнорирование его пакетов.

Клиент поддерживает графический интерфейс на базе Swing с отправкой данных по нажатию клавиши **Home** (через механизм Key Bindings), автоматическое подключение при запуске, асинхронный приём ответов от сервера в отдельном потоке и потокобезопасную запись всех событий сеанса в файл `client_log.txt`. При получении сообщения о разрыве соединения от сервера клиент корректно блокирует интерфейс и закрывает сокет.
