## Вариант 12

### Задание для сервера (табл. 2, №4):

После приема каждой группы из 64 символов от клиента сервер формирует и отсылает клиенту цепочку <«символ1-количество1», «символ2-количество2» и т.д.>, где «символ» - встреченный в группе символ, а «количество» - их количество в группе. ### Задание для клиента (табл. 3, №1):

- Возможность разрыва соединения при помощи команды: `disconnect`

## Описание реализации

В ходе работы было разработано клиент-серверное приложение на языке Java с использованием библиотеки `java.net`. Приложение реализует обмен данными по протоколу TCP.

### Сервер

- Ожидает подключения клиентов на порту 666 (`ServerSocket`)
- Для каждого клиента создаётся отдельный поток — класс `ClientHandler` реализует интерфейс `Runnable`, что позволяет обслуживать несколько клиентов параллельно
- Принимает от клиента строки текста и накапливает их в буфере
- При накоплении 64 символов формирует отчёт о частоте каждого символа в формате «символ-количество»
- Если в группе из 64 символов встречается менее 3 уникальных символов, сервер отправляет сообщение об ошибке и разрывает соединение
- Поддерживает команду `disconnect` для корректного завершения сеанса

### Клиент

Клиент представляет собой GUI-приложение на базе Swing с окном, содержащим:
- строку состояния (текущее состояние соединения),
- область вывода ответов сервера и логов (прокручиваемое текстовое поле),
- поле ввода строки,
- кнопку Disconnect.

**Особенности реализации:**
- Автоматическое подключение к серверу `localhost:666` при запуске
- Отправка строк происходит по нажатию клавиши **Home** (реализовано через механизм Key Bindings в Swing)
- Ведение файла протокола событий `client_log.txt` (в каталоге запуска клиента). В файл записываются с метками времени:
  - момент установки соединения и его параметры (хост и порт),
  - отправленные серверу строки и время их передачи,
  - принятые от сервера строки и время их приёма,
  - момент и причина закрытия соединения (пользователем или сервером),
  - сообщения об ошибках подключения
- При получении от сервера сообщения о разрыве соединения (менее 3 уникальных символов) клиент блокирует поле ввода и закрывает сокет
- Корректное закрытие окна через кнопку Disconnect или крестик в любой момент работы

## Запуск

### Требования

- ОС Windows (или любая ОС с установленной JDK)
- JDK (Java Development Kit) версии 8 или выше
- Свободный порт 666

### Порядок запуска

1. Разместите файлы `TCPServer.java` и `TCPClientGUI.java` в рабочем каталоге

2. Скомпилируйте классы:
   ```bash
   javac TCPServer.java TCPClientGUI.java
   ```

3. Запустите сервер:
   - В отдельном окне терминала запустите `java TCPServer`
   - В консоли появится: `TCP Server started on port 666`

4. Запустите клиент (не закрывая окно сервера):
   - Запустите в консоли `java TCPClientGUI`
   - Откроется графическое окно с автоматическим подключением к серверу

5. Проверка работы:
   - Введите текст в поле ввода и нажмите клавишу **Home** — текст отправится на сервер
   - Введите ровно 64 символа (например, `aaaabbbbccccddddeeeeffffgggghhhhiiiijjjjkkkkllll12345678901234`) и нажмите Home — сервер вернёт отчёт о частоте символов
   - Введите 64 одинаковых символа (например, 64 буквы 'a') и нажмите Home — сервер вернёт ошибку и разорвёт соединение
   - Введите команду `disconnect` и нажмите Home для корректного завершения сеанса

## Файл протокола

Все события клиента записываются в файл `client_log.txt` в каталоге запуска клиента. Пример содержимого:

```
[2026-10-27 14:23:15] Connection started to localhost:666
[2026-10-27 14:23:15] Connection established successfully.
[2026-10-27 14:23:40] Sent to server: "aaaabbbbccccddddeeeeffffgggghhhhiiiijjjjkkkkllll12345678901234"
[2026-10-27 14:23:40] Received from server: "a-4 b-4 c-4 d-4 e-4 f-4 g-4 h-4 i-4 j-4 k-4 l-4 1-1 2-1 3-1 4-1 5-1 6-1 7-1 8-1 9-1 0-1"
[2026-10-27 14:24:10] Command: disconnect
[2026-10-27 14:24:10] Connection ended.
```

В ходе выполнения лабораторной работы было успешно разработано клиент-серверное приложение на языке Java с использованием библиотеки `java.net`. Освоены основные этапы работы с TCP-сокетами: создание серверного сокета (`ServerSocket`) и ожидание подключений (`accept`), установка соединения на клиенте (`Socket`), организация потокового ввода-вывода через `BufferedReader`/`PrintWriter`, корректное закрытие сокета.

Сервер корректно обрабатывает группы из 64 символов, формирует отчёт о частоте символов и разрывает соединение при нарушении условия (менее 3 уникальных символов). Клиент поддерживает графический интерфейс с отправкой данных по нажатию клавиши Home, автоматическое подключение при запуске и потокобезопасную запись всех событий сеанса в файл `client_log.txt`.
