# АиПОС — Лабораторные работы

Данный репозиторий предназначен для централизованного хранения, сдачи и проверки лабораторных работ студентов группы.

## 1. Общие правила

1. Каждая лабораторная работа должна находиться в отдельной папке.
2. Название папки должно соответствовать установленному формату.
3. В папке должны находиться все необходимые исходные файлы для проверки и запуска работы.
4. Запрещено изменять, удалять или переименовывать папки других студентов.
5. Все работы отправляются на проверку через **Pull Request**.
6. Лабораторная работа считается загруженной после создания Pull Request, а принятой в репозиторий — после его одобрения и объединения с основной веткой.
7. Каждый студент несёт ответственность за содержимое загруженной работы.

## 2. Правила именования папок

Все лабораторные работы размещаются в каталоге `Labs`.

Название каждой папки должно соответствовать формату:

`Фамилия-Имя-Отчество-НомерЛабораторной`

## 3. Структура репозитория

```text
AiPOS-Labs/
│
├── README.md
│
└── Labs/
    ├── Иванов-Иван-Иванович-1/
    │   ├── main.cpp
    │   └── README.md
    │
    ├── Иванов-Иван-Иванович-2/
    │   └── ...
    │
    ├── Петров-Петр-Петрович-1/
    │   └── ...
    │
    └── Сидорова-Анна-Игоревна-1/
        └── ...
```

Каждый студент самостоятельно создаёт папку для своей лабораторной работы.

Внутри должны находиться исходный код программы и все необходимые файлы проекта.

**Не следует загружать** временные файлы, исполняемые файлы, кэш, папки сборки и другие автоматически генерируемые материалы, если они не требуются.

## 4. Как загрузить лабораторную работу

### Шаг 1. Создать копию репозитория (Fork)

1. Откройте ссылку на общий репозиторий, предоставленную преподавателем.
2. Нажмите кнопку **Fork** в правом верхнем углу.
3. Выберите свою учётную запись в качестве владельца.
4. Нажмите **Create fork**.

Теперь у вас есть собственная копия репозитория, в которую можно добавлять файлы.

### Шаг 2. Создать папку лабораторной работы

1. Откройте свою копию репозитория.
2. Перейдите в папку `Labs`.
3. Нажмите **Add file → Create new file**.
4. В поле имени файла введите путь:

   `Иванов-Иван-Иванович-1/README.md`

   Вместо указанного ФИО используйте своё, а вместо `1` — номер лабораторной.

5. В открывшемся редакторе напишите краткую информацию о работе:

   ```markdown
   # Лабораторная работа №1

   Студент: Иванов Иван Иванович

   Описание: Краткое описание выполненной работы.

   Запуск: Инструкция по запуску программы.
   ```

6. Нажмите **Commit changes** для сохранения файла.

GitHub автоматически создаст необходимую папку.

### Шаг 3. Загрузить исходные файлы

1. Откройте созданную папку.
2. Нажмите **Add file → Upload files**.
3. Перетащите необходимые файлы проекта в область загрузки или выберите их через проводник.
4. Проверьте список файлов.
5. Нажмите **Commit changes**.

**Важно:** убедитесь, что файлы добавлены именно в вашу папку с ФИО и номером лабораторной.

### Шаг 4. Отправить работу на проверку

1. Перейдите на страницу своей копии репозитория.
2. Нажмите **Contribute → Open pull request** (либо **Compare & pull request**, если GitHub показывает соответствующее уведомление).
3. Проверьте, что изменения отправляются в исходный репозиторий, в ветку `main`.
4. В заголовке Pull Request укажите:

   `Иванов Иван Иванович — Лабораторная работа №1`

5. В описании напишите, что реализовано в лабораторной работе.
6. Нажмите **Create pull request**.

**Не нужно нажимать Merge pull request самостоятельно.** Объединение изменений выполняет преподаватель после проверки.

## 5. Как отправить следующую лабораторную работу

Для каждой следующей работы необходимо:

1. Открыть свой Fork.
2. Перед началом работы нажать **Sync fork → Update branch**, если GitHub предлагает обновление.
3. Перейти в папку `Labs`.
4. Создать новую папку по установленному шаблону.
5. Загрузить файлы новой лабораторной.
6. Создать новый Pull Request.

Например, после сдачи первой лабораторной:

`Иванов-Иван-Иванович-1`

Для второй необходимо создать отдельную папку:

`Иванов-Иван-Иванович-2`

Не нужно удалять предыдущие работы или загружать новую лабораторную поверх старой.

**Важно:** перед отправкой новой лабораторной предыдущий Pull Request должен быть закрыт или принят. Если предыдущая работа ещё проверяется, новую можно подготовить в отдельной ветке своего Fork.
